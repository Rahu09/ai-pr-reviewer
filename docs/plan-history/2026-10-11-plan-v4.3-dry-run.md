# Plan change: v4.2 → v4.3, pre-build dry run (11 Oct 2026)

- **Before:** [2026-10-11-plan-v4.2-snapshot.md](2026-10-11-plan-v4.2-snapshot.md)
- **After:** [PLAN.md](../../PLAN.md) v4.3
- **New records:** [docs/pitfalls.md](../pitfalls.md), [ADR-0019](../decisions/0019-review-only-trusted-prs-cost-guard-from-sprint-1.md), and an ADR-0015 addendum (image build).
- **Trigger:** the owner asked for a final check done by *imagining following the plan step by step* and fixing whatever would break.

## Method
I walked every build day and chunk as if executing it on this workstation (Windows 11, `E:\production`, other local projects present), using the actual stack versions. I checked the risky facts against official docs on 2026-10-11 (the Spring Boot 4.0 migration guide and the Testcontainers 2 docs).

## Biggest risk found
**The stack is newer than most AI assistants' training data:** Spring Boot 4, Jackson 3, Testcontainers 2, Spring AI 2, Spring Kafka 4 and Java 25. On a 2-day timeline, "code from memory" compile errors would eat the schedule.

**Fix:** a version reality check (pitfalls §0) plus CLAUDE.md rules: generate from start.spring.io, verify APIs against the docs or sources, and record every new trap in pitfalls.md.

## Issues found and how they were fixed

| Where | Would have broken because… | Fix |
|---|---|---|
| Day 0 tools | smee needs **Node.js**; the ONNX runtime needs the **VC++ runtime** on Windows; an old `JAVA_HOME` | Added to the pre-Day-1 list |
| Chunk 0 | `.env` contents undefined; Spring Boot **doesn't read `.env`**; backslashes in paths break `.properties` parsing | Listed every variable; `spring.config.import` of `.env`; forward slashes |
| Chunk 1 | Boot 4 starters renamed or split (`webmvc`, **Flyway starter**), `@MockBean` removed; CI `mvnw` **Permission denied** (Windows drops the exec bit); port clashes with other local projects | start.spring.io pom as-is; `git update-index --chmod=+x`; host ports 5433/9094/8081 |
| Chunk 1/3 CI | Spring AI auto-config needs a key, so **tests and CI would fail** without one | Test profile with `spring.ai.model.chat=none` and a stub generator; tests never call real APIs |
| Chunk 2 | Hand-written diffs break the parser; diffs inside JSON are unreadable | Fixtures are **folders**, generated from real git branches |
| Chunk 3 | One unknown enum value fails the whole LLM response; `.entity()` loses token usage; `{}` in Java code clashes with prompt templates | `String` fields with strict validation; `responseEntity`; diff passed as a template variable |
| Chunk 4/10 | Posting big fixture JSON from Python | `POST /api/dry-run/fixture/{id}` + `FixtureLoader` |
| Chunk 5 | jsonb, timestamp and uuid binding errors | `CAST(:x AS jsonb)`, `timestamptz`↔`Instant`, `uuid`↔`UUID` |
| Chunk 6 | `GITHUB_TOKEN` collides with `gh` and Actions; contents arrive as base64 | `GITHUB_PAT`; raw media type |
| Chunk 7 | One bad inline comment makes GitHub reject the **whole** review (422) | One summary-only re-post, recorded |
| Chunk 11 | GitHub App key is **PKCS#1** (Java needs PKCS#8); JWT claims and clock drift; signature over a re-serialized body; **public repo lets strangers trigger paid reviews**; review starting before the delivery commits | Convert the key; JDK-only JWT recipe; raw bytes; **ADR-0019** (trusted PRs + daily cap from Sprint 1); after-commit trigger |
| Chunk 8 | JDBC can't bind `vector`; guessed thresholds; first-call model download; provider starters registering their own embeddings | `CAST(:q AS vector)`; tune on fixtures; cache directory; `spring.ai.model.embedding=transformers` |
| Chunk 10 | Free-tier 429s; the app must be running | Throttle + retry; noted |
| Chunk 12 | Kafka **listener** mix-up (host versus container); Kafka UI on port 8080; Spring Kafka JSON serializer type and trusted-package errors; "Kafka down" Testcontainers test impossible (new port on restart) | Two listeners; UI on 8081; String payloads + our own `JsonMapper`; failing-then-succeeding `KafkaTemplate` test plus a manual check |
| Chunk 13 | "Kill the app" can't run inside a test | Simulated crash in a test, plus one manual kill |
| Chunk 14 | arm64 build under QEMU is very slow; GHCR names must be lowercase and packages may be private; **Oracle iptables** block 80/443; Caddy before DNS; model re-download on each deploy | CI-built jar + runtime-only multi-arch Dockerfile (ADR-0015 addendum); visibility check; open iptables and the Security List; DNS first; cache volume |
| Session prompts | Hard-coded chunk lists would **skip** a chunk if a day overran (e.g. Day 1 not finishing Chunk 5) | Prompts are **status-driven**: start at the first chunk in §9.1 not marked Built |
| Session prompts | Reading all of PLAN.md every session wastes context on long build days | Read §9.0/§9.1/§10 plus only today's cards |

## What did NOT change
The architecture, scope, sprint structure, ADR decisions (except the ADR-0015 build detail, recorded as an addendum) and the documentation system.
